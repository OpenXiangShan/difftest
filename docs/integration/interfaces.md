# DiffTest Probe and Top-Level Interfaces

This page lists the current probe bundles and the top-level interface generated by `SimTop`. The source of truth is [`Bundles.scala`](../../src/main/scala/Bundles.scala) together with the `Diff*` wrappers in [`Difftest.scala`](../../src/main/scala/Difftest.scala).

## Mandatory Probes

| Probe | Purpose |
|-------|---------|
| `DiffArchEvent` | Exceptions, interrupts, and architectural trap events |
| `DiffInstrCommit` | Committed instructions and register writeback information |
| `DiffTrapEvent` | Simulation environment call and trap completion |
| `DiffCSRState` | Architectural CSR state |
| `DiffPhyIntRegState` | Physical integer registers; use 32 registers for an architectural register file |

The register-state bundle serves as the architectural integer-register state when `numPhyRegs` is 32. Designs with more physical registers should also connect the rename-table and delayed-update probes.

| Probe | Mandatory | Purpose |

| `DiffArchFpRenameTable` | No | Floating-point architectural-to-physical rename table |
| `DiffArchVecRenameTable` | No | Vector architectural-to-physical rename table |
| `DiffArchIntDelayedUpdate` | No | Delayed integer architectural writeback |
| `DiffArchFpDelayedUpdate` | No | Delayed floating-point architectural writeback |

Optional probes should be instantiated only when the corresponding architectural or microarchitectural behavior exists. A probe that is present but never produces valid events is not equivalent to a correctly disabled feature.

## DifftestTopIO

`DifftestModule.top` wraps the CPU in a `SimTop` module with this control interface:

| Field | Direction | Purpose |
|-------|-----------|---------|
| `exit` | Output | DUT exit status |
| `step` | Output | Current DiffTest step or cycle count |
| `perfCtrl.clean` | Input | Clear performance counters |
| `perfCtrl.dump` | Input | Dump performance counters |
| `logCtrl.begin` | Input | Start cycle for detailed logging |
| `logCtrl.end` | Input | End cycle for detailed logging |
| `logCtrl.level` | Input | Logging level |
| `uart.in.valid` | Output | CPU is ready to accept a UART input byte |
| `uart.in.ch` | Input | UART input byte supplied by the simulator |
| `uart.out.valid` | Output | CPU UART output is valid |
| `uart.out.ch` | Output | CPU UART output byte |

Use `connectTopIOs(difftest: DifftestTopIO)` in `HasDiffTestInterfaces` to connect CPU-specific UART and control ports.

## DifftestMemIO

```scala
case class DifftestMemIO(cpu: Record, mem: Option[Record] = None)
```

`cpu` is the CPU-facing memory record. `mem` optionally exposes the downstream memory-side record. For FPGA integration, pass this value from `difftestMemIO`; for ordinary DPI-C memory integration, use `DifftestMem` instead.

## Bundle Ordering and ABI

The generated DPI-C structs and function names depend on the exact bundle types, parameters, ordering, and count. If one of these changes:

1. Regenerate RTL and C++ interfaces.
2. Rebuild the C++ runtime from the same DiffTest revision.
3. Rebuild any reference model or plugin that consumes generated headers.
4. Verify MicroBench before enabling optimized transport modes.

Do not hand-edit generated headers under `build/`.
